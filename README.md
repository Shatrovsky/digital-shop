## Ключевые решения
Разделение очередей на "быструю" обработка `webhooks` и доставки `delivery`
в `webhooks` ответ отдается сразу с 200 статусом

### Идемпотентность вебхуков
1) в очередь `webhooks` попадают только новые вехуки, событие с одинаковым `event_id` обрабатывается один раз
2) при параллельной обработкм нескольких вебхуков по одному заказу, только один "залочит" заказ и произведет по нему попытку выдачи   

### Идемпотентность выдачи
1) по одному `request_id` происходит только одна выдача, вне зависимости от доступности поставщиков

## Масштабирование
1) очереди я уже разделил, чтобы выдача заказов не мешало обработке вебхуков
2) можно добавить воркеры, в зависимости от нагрузки
3) сейчас я использовал стандартные очереди из коробки, лучше использовать брокеры типа RabbitMQ
